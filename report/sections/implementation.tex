\subsection{Experiment registry}
The project is organized as fourteen numbered experiments (E01--E14), each a self-contained script
in \texttt{experiments/} driven by its own YAML config in \texttt{configs/}, run through a common
registry and runner (\texttt{experiments/registry.py}, \texttt{experiments/runner.py}) so that
\texttt{python -m experiments.runner E07} (or \texttt{make experiment ID=E07}) is enough to
reproduce any single result. Table~\ref{tab:course} lists what each experiment computes and the
code it exercises; at a coarser grain, E01--E04 characterize the solvers themselves against the
gold standard (convergence order, invariant drift, a stability frontier, and peak-accuracy
structure), E05--E06 characterize the estimation machinery (the cost landscape and an
optimizer shoot-out), E07--E11 form the core solver-in-the-loop recovery study (bias, noise
degradation, sampling/window effects, initial-condition sensitivity, and the four-way uncertainty
quantification), E12--E14 extend the pipeline (model variants, the crossover $\sigma^*$
search, and the real Eyam-1666 dataset).

\subsection{Configuration and profiles}
Every config file defines two profiles, \texttt{quick} and \texttt{full}, selected by
\texttt{make experiment ID=E\emph{nn} PROFILE=\{quick,full\}}. \texttt{quick} is sized to run
interactively (seconds to a few minutes per experiment) and is what every number in
Section~\ref{sec:results} uses; \texttt{full} matches the factorial sizes in our original
project plan and is intended for an offline or overnight run. As an example, E07's factorial
crosses 3 solvers $\times$ 2--6 step sizes $\times$ 3--6 noise levels $\times$ 2--5 sampling
intervals $\times$ 2--9 $(\beta,\gamma)$ regimes $\times$ 10 (\texttt{quick}) or 200
(\texttt{full}) replicates, giving a \texttt{full}-profile design of roughly $1.9\times10^6$
individual least-squares fits; \texttt{quick} runs a small slice of the same grid so the
qualitative scaling in Figure~\ref{fig:e07} is already visible without the overnight run. Each
config records the base seed, the model's true $(\beta,\gamma,N,I_0)$, the observation window and
sampling interval, and (for the replicate experiments) the number of parallel worker processes;
Section~\ref{sec:rng} gives the per-replicate seed derivation that makes the parallel workers
reproducible regardless of scheduling order.

\subsection{Datasets and benchmarks}
Every experiment except E14 fits synthetic data generated from the gold-standard trajectory or an
RK4 reference solve at $h=0.1$, with additive Gaussian noise at a controlled fraction of peak
prevalence (Eq.~\ref{eq:noise}); using data generated from the same model family being fit is a
deliberate design choice that isolates solver- and noise-induced error from any question of
model misspecification (see Section~\ref{sec:threats}). E14 fits the one real-world benchmark in
the project, digitized daily susceptible counts from the 1665--1666 plague outbreak in Eyam,
Derbyshire ($N=261$, $I_0=7$), the standard small-population teaching dataset for SIR fitting; we
flag in \texttt{data/raw/provenance.md} that the digitized counts have not yet been independently
verified against the primary source (Raggett, 1982), so we report E14 as a demonstration of the
pipeline rather than a validated epidemiological estimate. As a structural benchmark, every
hand-written routine in \texttt{core/sirlab} is cross-checked in \texttt{tests/} against an
independent implementation --- our LU solves and eigenpairs against \texttt{numpy.linalg}, our
solvers' Jacobians against complex-step differentiation, and our TypeScript dashboard's solvers
and gold standard against fixtures generated by the Python core (to $10^{-9}$ and $10^{-6}$
respectively) --- so that a bug in one implementation is unlikely to silently pass as ``the
answer.''

\subsection{Reproducibility infrastructure}
Every run is content-hash cached (\texttt{sirlab.io.manifest}): a config's hash, the git commit,
the host, and the seed are recorded alongside its output in \texttt{results/*.json}, and an
unchanged config skips a rerun. Results are exported to a decimated schema
(\texttt{sirlab.io.export}, about 600 points per curve) consumed by both the LaTeX figures
(\texttt{scripts/make\_figures.py}) and the interactive web dashboard, so the two never disagree
about which numbers are being shown. \texttt{make all} regenerates every result, figure, and this
report from a clean clone.
