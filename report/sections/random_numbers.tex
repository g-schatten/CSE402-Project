\subsection{Random number generation}
\label{sec:rng}
Every stochastic step in the pipeline -- observation noise, optimizer start points, bootstrap
resampling, and the MCMC sampler -- draws from a single pseudo-random number generator (PRNG)
through NumPy's \texttt{Generator} interface~\cite{harris2020numpy}. Experiments E01--E04, E12,
and E14 are deterministic and draw no random numbers. We did not write the generator ourselves, so
this subsection states which algorithm produces each random quantity
(Table~\ref{tab:rng}); together with the seeds, that makes every stochastic result reproducible.

\paragraph{Uniform source: PCG64.} The generator that NumPy's \texttt{default\_rng(seed)}
returns is PCG64~\cite{oneill2014pcg}. Its core is the linear congruential method of the course
simulation textbook~\cite{banks2010}, run on a 128-bit state:
\begin{equation}
  X_{i+1} = (a X_i + c) \bmod 2^{128}, \label{eq:lcg}
\end{equation}
with a fixed 128-bit multiplier $a$ and an odd increment $c$, which gives the full period
$2^{128}$. A power-of-two-modulus LCG has weak low-order bits (bit $j$ of $X_i$ repeats with period
$2^{j+1}$), so PCG does not output $X_{i+1}$ directly. Instead it XORs the two 64-bit halves of
$X_{i+1}$ and rotates the result right by the top six bits of the state (the ``XSL-RR'' output
permutation), giving a 64-bit integer $Y_i$. A uniform double on $[0,1)$ is its top 53 bits,
$U_i = \lfloor Y_i / 2^{11} \rfloor \cdot 2^{-53}$, and a draw from $U(a,b)$ is $a + (b-a)U_i$.
PCG64 passes the TestU01 BigCrush battery~\cite{oneill2014pcg}; we did not rerun statistical
tests such as the chi-square or Kolmogorov--Smirnov uniformity tests~\cite{banks2010} ourselves.

\paragraph{Seeds and independent streams.} Each experiment config fixes a base seed $s_0$
(experiment E$k$ uses $s_0 = k$), and NumPy's \texttt{SeedSequence} hashes it into PCG64's 128-bit
state and 128-bit increment. The replicate experiments (E07--E10, E13) run in parallel worker
processes, so one shared stream would make each replicate's numbers depend on scheduling order.
Instead every replicate gets its own generator, seeded by
\begin{equation}
  s = \big(10^7 s_0 + \mathrm{CRC32}(\mathrm{key})\big) \bmod (2^{31}-1), \label{eq:seed}
\end{equation}
where \emph{key} is a text string naming the factorial cell and replicate index (for E07: solver,
$h$, $\sigma$, $\Delta t$, $\beta$, $\gamma$, replicate number). We use CRC32 rather than Python's
built-in string hash because the latter is re-randomized in every process. A rerun with an
unchanged config therefore reproduces every replicate exactly, whatever the worker count. The
single-dataset experiments (E05, E06, E11) use one stream seeded with $s_0$; in E11 that stream
feeds, in order, the noise, the bootstrap, the Monte Carlo ensemble, and the MCMC starting points
and per-chain child seeds. No code uses NumPy's legacy global \texttt{np.random} state.

\paragraph{Gaussian observation noise.} All synthetic data use the additive Gaussian model
\begin{equation}
  \mathrm{obs}_k = I(t_k) + \sigma Z_k, \qquad Z_k \overset{\text{iid}}{\sim} \mathcal{N}(0,1),
  \label{eq:noise}
\end{equation}
with $\sigma = \sigma_{\mathrm{frac}} \max_k I(t_k)$. The clean prevalence $I(t_k)$ comes from the
gold standard (E07--E10, E13) or from an RK4 solve at $h=0.1$ (E05, E06, E11). The noise levels
quoted in Section~\ref{sec:results} are values of $\sigma_{\mathrm{frac}}$, i.e.\ fractions of peak
prevalence. NumPy draws each $Z_k$ with the ziggurat method~\cite{marsaglia2000ziggurat}, an
acceptance--rejection scheme that covers the normal density with 256 horizontal strips of equal
area. One 64-bit output picks a strip, a sign, and a point in the strip, and most points are
accepted after a single comparison; the rest go to an exact rejection test or a tail algorithm. The samples are exactly
$\mathcal{N}(0,1)$, as with the Box--Muller transform~\cite{banks2010}, but cost fewer operations.

\paragraph{Uniform draws.} Each Levenberg--Marquardt fit in E07--E09 starts from
$\theta_0 = \theta_{\mathrm{true}} \odot (U_1, U_2)$ with $U_j \sim U(0.6, 1.6)$; E10 and E13 use
$U(0.7, 1.4)$, and E10's 3-parameter fit also draws its $I_0$ start from
$I_{0,\mathrm{true}} \cdot U(0.5, 2)$. Random starts ensure that a recovered bias is not an
artifact of starting at the truth. E06 draws its multi-start points uniformly from the box
$\beta \in [0.05, 1]$, $\gamma \in [0.02, 0.5]$.

\paragraph{Resampling.} The residual bootstrap (E11) and the bootstrap confidence band on the RMSE
curve (E08, on its own stream seeded $s_0+1$) draw indices uniformly from $\{1, \dots, n\}$ with
replacement. NumPy produces bounded integers with Lemire's method~\cite{lemire2019}: it multiplies
a raw output by $n$ and keeps the high bits, rejecting the few outputs that would otherwise make
some indices more likely than others, so each index has probability exactly $1/n$.

\paragraph{MCMC draws.} Each Metropolis--Hastings iteration in E11 makes three draws.
(i) A proposal step $\varepsilon \sim \mathcal{N}(0, \Sigma_{\mathrm{prop}})$ in $u = \ln\theta$,
computed as $\varepsilon = A z$ with $z$ standard normal and $AA^\top = \Sigma_{\mathrm{prop}}$
from an SVD. $\Sigma_{\mathrm{prop}}$ starts at $\mathrm{diag}(0.02^2, 0.02^2)$; after iteration
200 it is reset every 100 iterations to $(2.38^2/2)$ times the sample covariance of the chain so
far (adaptive Metropolis~\cite{haario2001}). (ii) A uniform $U \sim U(0,1)$; the proposal $u'$ is
accepted if $\ln U < \ln \pi(u') - \ln \pi(u)$. The proposal is symmetric, so the Hastings ratio
reduces to the Metropolis ratio, and the target $\pi$ is the Gaussian likelihood with a flat prior
on $u$. (iii) A Gibbs update of the noise variance from its inverse-gamma conditional,
$\sigma^2 = 1/G$ with $G \sim \mathrm{Gamma}\big(2 + n/2,\ \text{rate } 1 + \mathrm{SSR}/2\big)$,
where the gamma variate comes from the Marsaglia--Tsang method~\cite{marsaglia2000gamma}, itself
an acceptance--rejection scheme driven by normal and uniform draws. The four chains start from
overdispersed points $\hat\theta \odot (U_1, U_2)$, $U_j \sim U(0.6, 1.6)$.

\paragraph{Noise models not used here.} \texttt{NoiseModel} also implements proportional
Gaussian, Poisson, and negative-binomial noise. NumPy generates Poisson variates by the
multiplication method for $\lambda < 10$ (multiply uniforms until the product falls below
$e^{-\lambda}$, the textbook algorithm~\cite{banks2010}), by transformed rejection for
$\lambda \ge 10$~\cite{hormann1993}, and negative-binomial variates as a gamma--Poisson mixture.
These models are available in the code, but none of the experiments reported here uses them.
